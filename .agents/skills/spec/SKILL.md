name: spec
description: Issue から実装用仕様書 (Markdown) を書く。Scope lock 付き。review スキルで自己レビューしてから完成させる。
---

指定された Issue を読み、実装に着手できる仕様書を Markdown で書く。コードの変更はしない (読み取りのみ)。

手順:

1. `gh issue view <番号>` で Issue 全文を読む。関連するコード・ドキュメントを読み取り、実態と Issue の記述の齟齬があれば仕様書に明記する
2. 仕様書を書く。冒頭に必ず `## Scope lock` を置き、次の3点を固定する:
   - 目的 (Issue の何を解決するのか1-2行)
   - やらないこと (Issue に書かれていても今回対象外とするもの)
   - 受け入れ条件 (どうなったら完成か。確認可能な形で箇条書き)
3. 続けて `## 設計` (変更対象ファイル・方針・注意点) を書く。推測で書かず、読んだコードを根拠にする
4. 書き上がったら review スキルの基準で自己レビューする (Blocker: 実害を説明できる欠陥だけ直す。Follow-up は仕様書末尾の `## Follow-ups` に逃がす)
5. 指定されたパスに仕様書を保存する。パス指定がなければ `tmp/spec-<issue番号>.md` に書く

注意: 顧客名・テナント slug・顧客データ由来の具体数値は仕様書に入れない (docs/agent-rules/confidentiality.md)。
